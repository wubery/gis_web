# Просмотрщик карт .mbtiles

Локальный веб-просмотрщик набора растровых `.mbtiles` из `D:\карты`.
Панорамирование, плавный зум, работа с телефона по локальной сети.

## Запуск

```powershell
cd "D:\карты\viewer"
npm start
```

Затем откройте адрес, который сервер напечатает в консоли — обычно
<http://localhost:8080/>.

Если проект разворачивается с нуля — см. [INSTALL.md](INSTALL.md).

## Управление

| Действие | Как |
|---|---|
| Панорамирование | перетаскивание мышью или пальцем (с инерцией) |
| Зум | колесо, `+` / `−`, двойной клик (с `Shift` — отдалить) |
| Зум на телефоне | щипок двумя пальцами |
| Сдвиг с клавиатуры | стрелки |
| Показать всё | кнопка `⤢` |

Текущий вид пишется в адресную строку (`#зум/широта/долгота`), поэтому
ссылку можно сохранить или переслать — карта откроется в том же месте.
Добавьте `?debug` к адресу, чтобы увидеть сетку тайлов и их номера.

## Доступ с телефона или планшета

Сервер слушает все интерфейсы, но Windows по умолчанию не пропускает
входящие соединения на порт 8080. Правило нужно создать один раз,
**в консоли, запущенной от имени администратора**:

```bash
netsh advfirewall firewall add rule name="mbtiles viewer 8080" dir=in action=allow protocol=TCP localport=8080
```

После этого открывайте на телефоне `http://192.168.1.139:8080/` (точный
адрес сервер печатает при запуске — берите тот, что из вашей Wi-Fi сети).

Правило открывает порт для всей локальной сети. Если это нежелательно,
удалить его можно так:

```bash
netsh advfirewall firewall delete rule name="mbtiles viewer 8080"
```

## Настройки

Задаются переменными окружения:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MAPS_DIR` | `D:\карты` | Где лежат `.mbtiles` |
| `PORT` | `8080` | Порт |
| `HOST` | `0.0.0.0` | `127.0.0.1` — закрыть доступ извне |
| `WORKERS` | `5` | Потоков чтения с диска |
| `CACHE_MB` | `256` | Кэш тайлов в памяти сервера |
| `RESCAN_MS` | `60000` | Как часто искать докопированные файлы |

В PowerShell переменные задаются через `$env:` **до** запуска (синтаксис
`VAR=значение команда` из bash здесь не работает). Пример — запуск только
для этого компьютера и с большим кэшем:

```powershell
cd "D:\карты\viewer"
$env:HOST = "127.0.0.1"; $env:CACHE_MB = "512"; npm start
```

## Как это устроено

```
Браузер (canvas)                 Node                          Диск
────────────────                 ──────────────────            ──────────
app.js                           server.js
 ├ pan / zoom / pinch             ├ HTTP + keep-alive
 ├ кэш ImageBitmap (600 шт)       ├ маршрут по клетке z9
 ├ подмена тайлами-предками       ├ LRU 256 МБ
 ├ очередь по приоритету (6)      └ 5 воркеров ────────────> 18 × .mbtiles
 └ предзагрузка на простое                                   (readonly)
```

Тайлы читаются прямо из `.mbtiles` — ничего никуда не распаковывается.
50 ГБ в виде отдельных файлов означали бы миллионы мелких файлов, на
которых NTFS сильно деградирует.

### Почему именно так

Карты лежат на HDD, и это определяет всю конструкцию: одно случайное
чтение стоит около 10 мс, а на экран нужно порядка сорока тайлов.
Отсюда четыре меры, в порядке значимости:

1. **Подмена предками.** Пока настоящий тайл грузится, на его место
   рисуется соответствующий кусок уже загруженного тайла с меньшего зума,
   растянутый до нужного размера. Картинка есть всегда — сначала мыльная,
   через доли секунды резкая. Проверено: прыжок на три уровня зума при
   пустом кэше даёт 100% покрытия экрана в тот же кадр.
2. **Пул воркеров.** `better-sqlite3` синхронный, и в главном потоке
   каждое чтение блокировало бы сервер целиком. Пять потоков позволяют
   диску держать несколько запросов сразу и переупорядочивать их.
3. **Два уровня кэша.** LRU в памяти сервера плюс `immutable` в браузере:
   тайл с данными координатами не меняется никогда, так что просмотренный
   район перестаёт создавать и сетевой трафик, и обращения к диску.
4. **Маршрутизация без ввода-вывода.** Каждый файл — это полная пирамида
   под одной клеткой z9. Для любого тайла глубже z9 нужный файл находится
   сдвигом координат, без единого обращения к диску.

Замер на этой машине (200 случайных тайлов z17, 6 параллельно):

| | p50 | p95 | тайлов/с |
|---|---|---|---|
| холодное чтение с HDD | 61 мс | 309 мс | 67 |
| повторное из кэша | 1.2 мс | 3.2 мс | 3581 |

### Если захочется сильно быстрее

Единственный рычаг крупнее всего перечисленного — перенести данные с HDD
на SSD. Диск `E:` пуст и на нём 118 ГБ свободно; случайное чтение там
быстрее в десятки раз. Переезд не требует правок кода:

```powershell
cd "D:\карты\viewer"
$env:MAPS_DIR = "E:\карты"; npm start
```

## Пока идёт копирование

Сервер сам определяет недокопированные файлы (сравнивает размер на диске
с тем, что записан в заголовке SQLite) и пропускает их, а раз в минуту
проверяет заново и подключает готовые без перезапуска. В просмотрщике
при этом показывается предупреждение со списком.

## Инструменты

```bash
node tools/bench.js 17 200 6
```

Замер отклика: зум, количество тайлов, параллельность. Первый проход —
цена настоящего попадания на диск, второй — то же самое из кэша.

```bash
node tools/dump.js C:\temp\tiles 9/305/172 10/610/344
```

Выгружает указанные тайлы в файлы. Полезно, чтобы глазами проверить
ориентацию и стыковку уровней.
