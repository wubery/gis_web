# Установка и развёртывание

Инструкция для разворачивания проекта с нуля на чистой машине.
Команды даны для **PowerShell** (стандартная консоль Windows); отличия
для cmd.exe и Linux/macOS отмечены отдельно.

---

## 0. Компьютер без интернета — берите готовый комплект

Всё, что описано ниже, нужно только если вы разворачиваете проект
из исходников. **Если на целевой машине нет интернета — этот путь вам
не подходит:** `npm install` там не выполнить, а Node.js не скачать.

Для такого случая собран автономный комплект `Просмотр карт.zip`.
В нём уже лежит всё: портативный `node.exe`, установленные зависимости
с готовыми бинарниками и сама программа. Ставить и качать ничего не надо,
права администратора не нужны.

```
Просмотр карт\
├── ЗАПУСТИТЬ.bat      <- двойной щелчок
├── ПРОЧТИ МЕНЯ.txt
├── карты\             <- скопировать сюда .mbtiles
└── app\               <- программа и node.exe
```

Порядок: распаковать папку куда угодно, положить `.mbtiles` в `карты\`,
запустить `ЗАПУСТИТЬ.bat`. Браузер откроется сам.

Подробности — в `ПРОЧТИ МЕНЯ.txt` внутри комплекта. Как комплект
пересобрать — в разделе 12.

Требования: Windows 10 или новее, 64 бита. Visual C++ Redistributable
и любые другие компоненты **не нужны** — `node.exe` из официальной
сборки Node.js слинкован статически и обращается только к системным
библиотекам Windows.

## 1. Что должно быть на машине

| Компонент | Версия | Обязателен | Зачем |
|---|---|---|---|
| Node.js | **22 или новее** | да | Среда выполнения сервера |
| npm | идёт с Node.js | да | Установка зависимости |
| Компилятор C++ | — | **нет** | Не нужен, см. ниже |

Проверено на Node.js 24.15.0 (Windows 11, x64).

### Компилятор не нужен, но есть нюанс

Единственная зависимость проекта — `better-sqlite3`. Это нативный модуль,
и обычно такие требуют Visual Studio Build Tools. Но пакет версии 13 везёт
**уже собранные бинарники** прямо в себе, а собран он на N-API, то есть
один и тот же файл работает с разными версиями Node:

```
win32-x64      win32-arm64
linux-x64      linux-arm64
linuxmusl-x64  linuxmusl-arm64
darwin-x64     darwin-arm64
```

Нюанс в поведении npm. В пакете лежит `binding.gyp`, и, увидев этот файл,
npm **сам** запускает `node-gyp rebuild` — даже когда в `scripts` никакого
install-скрипта нет. Сборка тут бессмысленна (бинарник уже готов), но
требует компилятора и качает заголовки Node с nodejs.org, а значит легко
валит установку на ровном месте. При проверке этой инструкции она и упала —
на `ECONNRESET` при скачивании заголовков.

Поэтому в проекте лежит `.npmrc` со строкой `ignore-scripts=true`. С ним
`npm install` отрабатывает меньше чем за секунду, ничего не компилирует
и ни от чего не зависит. Ничего дополнительно указывать не надо — npm
подхватывает `.npmrc` из папки проекта автоматически.

Компилятор понадобится, только если ваша платформа не в списке выше —
тогда см. последний пункт раздела «Если что-то не так».

### Ресурсы

- **Диск:** сам проект ~250 КБ, плюс ~27 МБ на `node_modules`.
  Карты занимают столько, сколько занимают (в исходном наборе ~50 ГБ).
- **Память:** сервер держит ~130 МБ плюс кэш тайлов (`CACHE_MB`, по
  умолчанию 256 МБ). Итого около 400 МБ.
- **Порт:** 8080 (меняется переменной `PORT`).

## 2. Установка Node.js

### Windows

Проверьте, не стоит ли уже:

```powershell
node --version
```

Если версия 22+ — переходите к шагу 3. Если команда не найдена или версия
старее, ставьте одним из способов.

**Через winget** (встроен в Windows 11):

```powershell
winget install OpenJS.NodeJS.LTS
```

**Или установщиком:** скачайте MSI с <https://nodejs.org/> (ветка LTS)
и пройдите мастер со значениями по умолчанию.

После установки **закройте и откройте консоль заново** — иначе `node`
не появится в `PATH` текущей сессии. Затем проверьте:

```powershell
node --version; npm --version
```

### Linux

Системный пакет `nodejs` в дистрибутивах часто слишком старый. Надёжнее
через nodesource или nvm:

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs
```

### macOS

```bash
brew install node@22
```

## 3. Распаковка проекта

Распакуйте `mbtiles-viewer.zip` в любую папку. Рекомендую положить рядом
с картами — тогда путь к ним не придётся настраивать вообще:

```
D:\карты\                                  <- папка с картами
├── Kharkov region 305х172 ....mbtiles
├── Kharkov region 305х173 ....mbtiles
├── ...
└── viewer\                                <- сюда распаковать архив
    ├── package.json
    ├── package-lock.json
    ├── .npmrc                             <- важен, см. раздел 1
    ├── server.js
    ├── lib\
    ├── public\
    ├── tools\
    ├── README.md
    └── INSTALL.md
```

Проверьте, что `.npmrc` распаковался: некоторые архиваторы прячут файлы,
начинающиеся с точки. Без него `npm install` попытается компилировать
модуль и, скорее всего, упадёт.

По умолчанию сервер ищет `*.mbtiles` **в родительской папке** относительно
себя. Если раскладка другая — путь задаётся переменной `MAPS_DIR`, см. шаг 6.

В архиве нет папок `node_modules` и `cache` — первая ставится следующим
шагом, вторая создаётся сервером сама.

## 4. Установка зависимости

```powershell
cd "D:\карты\viewer"
npm install
```

Ожидаемый вывод — примерно такой:

```
added 2 packages in 819ms
```

Два пакета — это `better-sqlite3` и его вспомогательный `node-addon-api`.
Если установка идёт дольше нескольких секунд и в выводе мелькает `node-gyp`
или `MSBuild` — значит `.npmrc` не на месте, см. раздел 3.

Проверить, что нативный модуль подхватился:

```powershell
node -e "const D=require('better-sqlite3'); const db=new D(':memory:'); console.log('OK, sqlite', db.prepare('select sqlite_version() v').get().v)"
```

Должно напечатать `OK, sqlite 3.53.4` (номер может отличаться).

## 5. Требования к файлам карт

Сервер работает со стандартными **MBTiles**:

- таблица `tiles(zoom_level, tile_column, tile_row, tile_data)`;
- индекс по `(zoom_level, tile_column, tile_row)` — без него всё будет
  работать, но медленно;
- растровые тайлы: **jpg**, **png** или **webp** (формат определяется
  автоматически по таблице `metadata` и по сигнатуре первого тайла);
- строки в схеме TMS — как и предписывает спецификация MBTiles.

Векторные тайлы (`pbf`) этот просмотрщик не рисует.

Файлов может быть сколько угодно, они могут перекрываться и иметь разные
диапазоны зумов — сервер строит по ним общую карту покрытия сам.

## 6. Настройки

Все настройки — переменные окружения, все необязательны.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MAPS_DIR` | родительская папка | Где искать `*.mbtiles` |
| `PORT` | `8080` | Порт |
| `HOST` | `0.0.0.0` | `127.0.0.1` закроет доступ из сети |
| `WORKERS` | `5` | Потоков чтения с диска |
| `CACHE_MB` | `256` | Кэш тайлов в памяти сервера |
| `RESCAN_MS` | `60000` | Как часто искать докопированные файлы |

**PowerShell** (синтаксис `VAR=значение команда` из bash здесь не работает,
и `&&` в PowerShell 5.1 тоже нет — команды разделяются `;`):

```powershell
$env:MAPS_DIR = "E:\карты"; $env:CACHE_MB = "512"; npm start
```

**cmd.exe:**

```
set MAPS_DIR=E:\карты
set CACHE_MB=512
npm start
```

**Linux / macOS:**

```bash
MAPS_DIR=/mnt/maps CACHE_MB=512 npm start
```

Про подбор `WORKERS`: значение по умолчанию рассчитано на HDD, где больше
пяти-шести параллельных читателей начинают мешать друг другу — головка
мечется, и суммарная скорость падает. На SSD или NVMe есть смысл поднять
до 8–12.

## 7. Первый запуск

```powershell
cd "D:\карты\viewer"
npm start
```

При первом старте сервер обходит все `.mbtiles` и строит таблицу
маршрутизации. Замер на исходной машине (HDD, 18 файлов, ~50 ГБ):
**345 секунд, около 19 секунд на файл.** Результат кладётся
в `cache/index.json`, и все последующие запуски занимают доли секунды.

Чтобы это не выглядело зависанием, сервер печатает ход работы по файлам:

```
[индекс] открываю   7/18  Kharkov region 306х174 ....mbtiles
...
[индекс] индексирую 7/18  Kharkov region 306х174 ....mbtiles
...
[индекс] старт: 18 файлов готово, 0 пропущено (собран за 344871 мс)
[индекс] зумы 0–18, формат jpg, границы 34.453, 48.458, 37.266, 50.736

[сервер] воркеров: 5, кэш: 256 МБ
[сервер] открывайте:
           http://localhost:8080/
           http://192.168.1.139:8080/
```

Фаз две, потому что и работы две: сначала каждый файл открывается
и проверяется на целостность, потом по низким зумам собирается таблица
маршрутизации. Обе упираются в случайное чтение с диска.

Откройте <http://localhost:8080/>. Остановка — `Ctrl+C`.

### Если часть файлов ещё копируется

Сервер сравнивает размер файла на диске с тем, который записан в заголовке
SQLite, и недокопированные пропускает — иначе любой запрос к ним падал бы
с ошибкой «database disk image is malformed». Раз в минуту он проверяет
заново и подключает дозревшие файлы **без перезапуска**. В просмотрщике
при этом висит предупреждение со списком и процентами.

## 8. Проверка, что всё поднялось

```powershell
Invoke-WebRequest http://127.0.0.1:8080/api/info -UseBasicParsing | Select-Object -ExpandProperty Content
```

Должен вернуться JSON с `minzoom`, `maxzoom`, `bounds`, `filesReady`.

Замер скорости чтения (зум, число тайлов, параллельность):

```powershell
node tools/bench.js 17 200 6
```

Первый проход — цена реального обращения к диску, второй — то же самое
из кэша. На исходной машине (HDD, 50 ГБ тайлов) вышло p50 177 мс против
p50 1.4 мс — разрыв в сто с лишним раз.

Имейте в виду: случайные тайлы по всему массиву — намеренно худший
сценарий. При обычном просмотре карты запросы идут по соседним тайлам,
и почти всё берётся из кэша.

Текущее состояние кэша и воркеров:

```powershell
Invoke-WebRequest http://127.0.0.1:8080/api/stats -UseBasicParsing | Select-Object -ExpandProperty Content
```

## 9. Доступ с телефона и планшета

Сервер слушает все интерфейсы, но Windows не пропускает входящие
соединения на порт 8080, пока не разрешить явно. Правило создаётся один
раз, **в консоли, запущенной от имени администратора**:

```
netsh advfirewall firewall add rule name="mbtiles viewer 8080" dir=in action=allow protocol=TCP localport=8080
```

Затем на телефоне откройте `http://<адрес компьютера>:8080/`. Нужный адрес
сервер печатает при запуске — берите тот, что из вашей Wi-Fi сети (обычно
`192.168.x.x`). Телефон и компьютер должны быть в одной сети.

Правило открывает порт для всей локальной сети. Удалить:

```
netsh advfirewall firewall delete rule name="mbtiles viewer 8080"
```

Если сеть публичная или недоверенная — правило лучше не создавать, а сервер
запускать с `$env:HOST = "127.0.0.1"`, тогда он будет доступен только
с самого компьютера.

## 10. Автозапуск (необязательно)

### Ярлык в автозагрузке — самый простой способ

Создайте файл `D:\карты\viewer\start.cmd`:

```
@echo off
cd /d "D:\карты\viewer"
node server.js
```

Нажмите `Win+R`, введите `shell:startup`, и положите в открывшуюся папку
ярлык на этот файл. Сервер будет стартовать при входе в систему в окне
консоли.

### Планировщик заданий — если нужен старт без входа в систему

В консоли администратора:

```
schtasks /create /tn "mbtiles viewer" /tr "node D:\карты\viewer\server.js" /sc onstart /ru SYSTEM /f
```

Учтите: под `SYSTEM` сетевые диски недоступны — карты должны лежать
на локальном диске.

## 11. Если что-то не так

**`node` не найден после установки** — консоль не перечитала `PATH`.
Закройте её и откройте заново.

**`Ни одного пригодного .mbtiles в ...`** — сервер смотрит не туда либо
файлы ещё копируются. Проверьте путь, который он напечатал, и задайте
`MAPS_DIR` явно.

**`EADDRINUSE`** — порт 8080 занят. Возьмите другой:

```powershell
$env:PORT = "8081"; npm start
```

Посмотреть, кто занял порт:

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object OwningProcess
```

**`npm install` падает с ошибкой сети** — за корпоративным прокси задайте
его для npm:

```
npm config set proxy http://прокси:порт
```

**`npm install` пытается компилировать** и падает на `node-gyp`, `MSBuild`
или на скачивании `node-vXX-headers.tar.gz` — первым делом проверьте, лежит
ли в папке проекта файл `.npmrc` с `ignore-scripts=true` (раздел 1). Чаще
всего его просто не распаковал архиватор. Разовый обход без него:

```
npm install --ignore-scripts
```

**Модуль не грузится**: `Could not locate the bindings file` или
`invalid ELF header` — вот это уже значит, что готового бинарника под вашу
платформу в пакете нет и его действительно надо собрать:

```
npm rebuild better-sqlite3
```

Для этого нужны Python 3 и компилятор C++. На Windows —
[Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
с компонентом «Разработка классических приложений на C++»; на Debian/Ubuntu —
`sudo apt install build-essential python3`.

**Телефон не открывает страницу** — по порядку: создано ли правило
брандмауэра; тот ли IP (при активных VPN и виртуальных машинах сервер
печатает несколько адресов, нужен из вашей Wi-Fi подсети); в одной ли
сети устройства; не включена ли на роутере изоляция клиентов.

**Карта грузится медленно при первом просмотре** — так и есть на HDD,
это цена случайного чтения. Повторный просмотр того же района идёт
из кэша практически мгновенно. Радикально помогает только перенос
карт на SSD.

**Карта пустая, в консоли одни 204** — проверьте, что тайлы растровые,
а не векторные (`format` в `metadata` должен быть `jpg`/`png`/`webp`),
и что схема стандартная (см. шаг 5).

## 12. Пересборка автономного комплекта

Нужна, если вы поменяли код и хотите обновить комплект из раздела 0.
Делается на машине **с** интернетом и установленным Node.js, один раз:

```powershell
cd "D:\карты\viewer"
npm install
powershell -ExecutionPolicy Bypass -File tools\build-bundle.ps1 -Zip
```

Скрипт складывает в `..\Просмотр карт\` программу, `node_modules`
и `node.exe` от текущего Node, чистит кэш указателя и приводит текстовые
файлы к виду, который понимает «Блокнот». Ключ `-Zip` заодно пакует архив.

Что именно попадает в комплект и почему:

| Что | Зачем |
|---|---|
| `node.exe` | Среда выполнения. Один файл, ~87 МБ, ничего не требует |
| `node_modules\` | `better-sqlite3` с готовыми бинарниками под все платформы |
| `lib\`, `public\`, `server.js`, `start.js` | Сама программа |
| `cache\` | Пустая; указатель строится при первом запуске |

Две вещи, на которых легко обжечься:

- **`ЗАПУСТИТЬ.bat` должен быть чистым ASCII.** Батник читается консолью
  в её текущей кодировке, и кириллица внутри превратится в мусор на машине
  с другими настройками. Поэтому весь русский текст печатает Node (он всегда
  выдаёт UTF-8), а в батнике стоит `chcp 65001`. По той же причине служебная
  папка названа `app`, а не «программа»: её имя подставляется в путь прямо
  из батника. Скрипт сборки проверяет это и предупреждает.

- **Кэш указателя в комплект не кладётся.** В `cache/index.json` записаны
  абсолютные пути машины сборки; на целевой он всё равно будет отброшен
  по несовпадению отпечатка, но будет сбивать с толку при разборе проблем.

Проверить собранный комплект, не полагаясь на системный Node:

```powershell
$sys = $env:SystemRoot
$env:PATH = (Join-Path $sys 'System32') + ';' + $sys   # прячем установленный Node
& "..\Просмотр карт\ЗАПУСТИТЬ.bat"
```

Сервер должен подняться и открыть браузер. Если вместо этого окно
закрылось — значит `node.exe` не скопировался или батник испорчен.
